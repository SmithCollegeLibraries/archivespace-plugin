# AGENTS.md

Guidance for AI coding agents working in this repository. `CLAUDE.md` imports this file; edit
here only.

## What this is

`digital_viewer`, an ArchivesSpace Public User Interface plugin that renders digital objects with
OpenSeadragon. It must be installed in a plugin directory named `digital_viewer`.

## Build and test

Use the pinned Node and npm versions (`.nvmrc`, `package.json`). From the repository root, install
the pinned JavaScript and Ruby development dependencies once after cloning or changing the lockfile:

```sh
npm ci
BUNDLE_GEMFILE=tools/rubocop/Gemfile bundle install
```

Run checks from the repository root:

```sh
npm run lint
BUNDLE_GEMFILE=tools/rubocop/Gemfile bundle exec rubocop plugin_init.rb public/ test/
npm run check:generated
npm test
ruby test/asset_version_test.rb
ruby test/fallback_template_test.rb
```

- `src/` is the authoritative JavaScript. `public/assets/digital_viewer.js` and its source map are
  generated by `npm run build` and committed. Never edit them by hand; rebuild and commit both.
- `check:generated` must pass before you report a change as done.
- Browser checks in `test/browser/` need a running ArchivesSpace; see `test/browser/README.md`.
  Passing local tests does not authorize installing on a hosted ArchivesSpace.
- `frontend/` holds historical copies. Do not edit them or use them as build inputs.

## Code standards

- Apply DRY and SOLID: give each module, class and function one responsibility.
- Keep complexity about 10, JavaScript functions about 40 lines, and Ruby methods at most 25 lines.
- Keep ESLint and RuboCop clear; track genuine refactors for follow-up.
- Keep the repository root free of `Gemfile`: ArchivesSpace installs it as a runtime dependency.

## Interfaces other systems depend on

Do not change these unless your task explicitly covers it. Report the change in your handoff,
because the repositories that depend on them must change at the same time.

| Interface | Defined in | Who depends on it |
|---|---|---|
| Recognised `file_uri` patterns and their priority order | `docs/plugin-source-contract.md`, `src/source-selection.mjs` | Catalogers and migration tooling; a backend that mirrors the same detection |
| `window.DigitalViewer` keys and their environment variables (`CANTALOUPE_PUBLIC_URL`, `COMPASS_BASE_URL`, `COMPASS_PROXY_URL`, `PRESERVICA_API_BASE`, `DIGITAL_VIEWER_LOADING_TIMEOUT_MS`) | `public/views/layout_head.html.erb` | Host configuration. An absent or empty value must disable the adapter, never fall back to localhost |
| The bubbling `digital-viewer:open` event with `detail.viewer` | README "Extension point", `src/viewer.mjs` | The `ocr_search` plugin's page highlights |
| Manifest canvas order and identity when opening a page | `src/manifest.mjs`, `src/page-sources.mjs` | Search results that open a specific page |

## Public repository rules

This repository is public and dedicated to the public domain under CC0 1.0.

- Keep project-management material out: no tickets, backlogs, review logs, evidence files,
  staff or vendor names, or internal hostnames. Use `example.org` in tests.
- Tests use synthetic records and URLs only.
- `public/assets/openseadragon.min.js` and `public/images/` are third-party (BSD-3-Clause). Do not
  modify them; keep `THIRD_PARTY_NOTICES.md` accurate if you update OpenSeadragon.
- Never add credentials or `.env` files.

## Working rules

- Work on a branch named for your task. Do not push, merge to `main` or tag releases; a reviewer
  does that.
- Keep to the files your task names. If the task is wrong or incomplete, stop and report.
- End with: branch and commit, every command run with its result, anything you changed beyond the
  task and why, and open questions.
